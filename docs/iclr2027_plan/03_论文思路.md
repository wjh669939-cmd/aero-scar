# ICLR 2027：论文思路 v1.0

> 日期：2026-08-23
> 原则：借鉴分子那篇 Closed-loop 论文（arXiv:2606.22731）的方法论骨架，但创新点必须是它没有的东西；所有主张对应到可执行的实验。

---

## 一、标题候选与一句话 thesis

标题候选（按推荐顺序）：

1. **Closed-Loop Auto Research for Aerodrome Weather Forecasting: Pre-Registered Discovery and Multi-Environment Certification**
2. Discovering and Certifying Improvements under Temporal, Spatial, and Extreme-Event Shifts: Closed-Loop Auto Research on an Operational Weather Task
3. （分支 B/D 备用）How Much of Closed-Loop Auto Research Gain Survives Certification? A Pre-Registered Measurement on Operational Aerodrome Forecasting

一句话 thesis：

> 闭环自动科研在真实运行级气象任务上发现的 validation 改进，只有经过预注册门槛、多 seed 配对确认和跨时间/机场/极端事件的一次性隐藏认证，才能区分真实科学发现与 selection variance / distribution shift；我们给出一套可执行的协议，并报告一次完整、可审计的实证。

## 二、研究问题

- **RQ1（发现）**：在冻结数据、预算、evaluator 与双轴动作边界下，LLM 驱动的闭环能否发现优于强 parent（我们自己的 KDD 2026 基线）且优于匹配预算随机搜索的候选？
- **RQ2（迁移）**：validation 选出的候选，在时间外推、未见机场（ZBAD）、极端天气事件三类隐藏环境上各自迁移多少？非迁移的部分属于 selection variance 还是 distribution shift？
- **RQ3（治理）**：预注册假设/证伪条件、文件级 axis lock、一次性 test 认证这套反作弊机制，在时序运行数据上需要哪些领域特有的构件（issue-time 因果、purge gap、事件块隔离），代价是什么？

## 三、贡献点：借鉴 vs 必须不同

| 分子论文已有（我们借鉴，引用并说明） | 我们的差异化（论文的创新点） |
|---|---|
| 单轴 axis lock 归因 | 同机制，但轴是气象领域的 Representation/Objective，且动作带**机制假设与证伪条件预注册**（他们无预注册环节） |
| 单一 held-out test 一次性认证 | **三类隐藏环境认证**（temporal / spatial-unseen-airport / extreme-event），输出每个候选的"迁移画像"而非单个 test 数字；这是对"分 regime 迁移"的正交扩展 |
| 分子污染过滤器（identity/same-source/analogue） | **时序运行数据的泄漏机制学**：issue-time 因果审计、96 步滑窗 purge gap、天气事件块隔离——分子过滤器在时序域的对应物，全部由 evaluator 侧持有 |
| 非迁移双签名（selection variance / distribution shift）的事后归因 | **把 selection variance 做成前置量化**：seed 方差 gate + 配对多 seed 确认 + block-bootstrap CI + 匹配预算随机对照，使"增益是否超出噪声"在冻结前就被判定 |
| 36 个 endpoint 的 suite 级分布 | 单数据集上用 **(任务 × 时效 × 机场) endpoint 网格**（约 20–27 个配对 endpoint）重建统计内容，并如实讨论单数据集局限 |
| AutoML 对照 | 升级为 P1（GPU 已不设限）：matched-trial 超参搜索对照（Optuna，同预算同 evaluator），若人时允许纳入主表；否则只做随机对照并如实说明 |

另有一条独有叙事线（如 tier-2 成立）：**agent 重新发现并修复我们自己已发表模型的缺陷**——KDD Table 3 中 Scratch 在 T+1 MAE 反超预训练模型，暗示统一几何对齐目标对短时效负迁移；若闭环独立提出"时距条件化对齐权重"并通过认证，这是"自动科研发现了作者自己没修的问题"的第一手案例。**前置条件**：该异常必须先在修复版代码（AeroWF†）上复现确认（阶段 1 验收项），因为公开仓库是中间版本、Table 3 数字不可完全复现。"故意留弱基线"质疑的防御改为三件套：基线校准预算在 discovery 前冻结、全部调参留痕入 lineage、方法本身经 KDD 同行评审（重建的是数字，不是方法）。

## 三·五、动作空间"设计原则"能否作为创新点（8/25 增补，严格评估）

**结论：作为独立卖点不行，作为预注册的可检验假设可以，而且应该。**

不行的理由：

1. "设计原则"本身不可证伪——我们没有预算跑一个"坏设计动作空间"对照，无法对设计做消融，a priori 原则在审稿人眼里是 careful experimental design，不是方法贡献；
2. n=1 领域、n=1 模型，从单案例归纳"原则"会被直接质疑过度概括；
3. 证据锚定、文件锁、单轴归因的大框架分子论文已占位，我们在这些点上只是移植。

可以升格的成分——**把"可参数化 vs 代码级动作"二分做成预注册假设**：

> **H-tax（预注册）**：LLM 臂相对随机臂/Optuna 臂的超额价值（接受率、认证迁移率）集中在 code_level 动作上；在 parameterizable 动作上三臂无显著差异。

依据：分子论文中 LLM 唯一击败 matched AutoML 的正是 model-code 轴；我们的三臂设计（LLM / 同空间随机 / Optuna 超参）+ registry 中每个动作已标注 `type: parameterizable | code_level`，恰好使这个假设可检验。**无论证实还是证伪都是可发表的发现**：证实 = 分子论文结论在新领域、新任务类型上的推广；证伪 = "LLM 推理的边际价值不在写代码"同样有信息量。这把"设计原则"从装饰变成了科学问题。

配套要求（写入实验协议）：

1. Table 3（trial 账本）增加按 action type 的分解列；
2. 报告接受候选中**自由提案 vs 模板动作**的占比——预防"动作空间是人设计的，功劳归人不归 LLM"的质疑；
3. 若三臂在两类动作上均无分化：该线降级为附录协议说明，不进贡献列表，不硬写。

## 五、备选叙事（分支 B / D 使用，价值不依赖正结果）

若 seed 方差过大或无候选通过确认，论文转为**预注册的可靠性测量**：

> "我们把分子领域证明有效的 Closed-loop Auto Research 协议移植到一个低信噪比、单数据集的运行级预测任务，预注册全部门槛后如实报告：X% 的 validation 增益不能通过多 seed 配对确认，Y% 不能通过隐藏环境认证；LLM 提案与匹配预算随机提案在接受率/机制合理性上差异为 Z。"

主张点变为：(1) 时序运行任务的认证协议本身；(2) selection variance 的量化；(3) 对"闭环自动科研在什么条件下产生可信发现"的边界刻画——与分子论文的正结果形成对照，这是审稿人无法用"结果不显著"一票否决的测量型贡献。风险如实评估：该叙事在 ICLR 的录取率低于主叙事，若触发分支 D，同步准备 ICML 版本。

## 六、允许与禁止的主张

允许：
- 在真实运行级气象数据与真实 GPU 路径上完成预注册闭环自动科研；
- 报告候选在三类隐藏环境上的迁移画像与完整负结果账本；
- （若认证通过）闭环发现了跨环境迁移的改进，且优于匹配预算随机搜索。

禁止：
- 声称通用空管/航空工程框架（单任务撑不起）；
- 声称 LLM 优于人类研究者（无该对照）；
- 用单 seed 或单环境结果声称"已认证发现"；
- 认证后再改候选或再搜索后重测；
- 把 KDD Table 3 数字与新协议数字混入同一表（协议不同：修 bug + purge gap + 三机场）。

## 七、预期审稿质疑与预答复

| 质疑 | 预答复 |
|---|---|
| 单数据集，何谈方法论？ | endpoint 网格 + 三环境认证提供分布级证据；定位为 pre-registered case study，与分子论文 36-endpoint 的 suite 级证据互补；局限如实写 |
| 这不就是超参搜索加仪式感？ | 动作是机制假设驱动的表示/目标干预（跑道坐标系物理量、时距条件化目标），配匹配预算随机对照证明 LLM 提案的超额价值；若 tier-2 成立，还有"发现已发表模型缺陷"的定性证据 |
| 私有数据可信吗？ | Aero-Dataset 随 KDD 2026 论文公开（GitHub + Zenodo DOI），方法经同行评审 |
| 基线与发表数字不一致？ | 如实说明：公开仓库为中间版本（作者确认），我们修复三处 bug、澄清预训练/下游遮挡协议（40%/25%）、增加 purge gap 与三机场设定后重建基线（记为 AeroWF†），修复清单与调参日志全部公开；本文所有主张基于配对相对增益，不依赖与 Table 3 的绝对可比性 |
| 与分子论文差异何在？ | 见 §3 表：预注册、三环境迁移画像、时序泄漏机制学、selection variance 前置量化，均为该文没有的构件 |
| 为什么没有 AutoML 对照/多次闭环重复？ | 超参搜索对照已列为 P1（视人时纳入）；多次闭环重复如实列为 limitation 与后续工作；随机对照是回答 RQ1 的最小充分控制 |
| 动作空间是人设计的，发现的功劳归人不归 LLM？ | 三点：模板同时是随机臂采样空间（LLM 的超额价值被隔离测量）；LLM 允许文件锁内自由提案，接受候选中自由提案占比如实报告；H-tax 预注册分解显示价值来源于哪类动作 |
