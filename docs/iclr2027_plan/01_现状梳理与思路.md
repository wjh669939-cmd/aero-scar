## 一、一句话定位

> 在我们自己的 KDD 2026 已发表强基线（AeroWF）上，用带预注册与反作弊治理的 Closed-loop Auto Research 发现模型/训练改进，并在**时间、空间（未见机场）、极端天气事件**三类隐藏环境上做一次性独立认证，回答"闭环自动科研发现的改进能否跨环境迁移"。

不做的事（与愿景图的差异）：

- 研究动作空间从 4 个轴砍成 **2 个轴**（Representation + Objective）；
- 不做通用空管框架（流量预测、冲突检测、运行优化不进本篇）；
- 不做 Data Axis 外部数据获取（需要污染过滤器体系，是另一个项目）；
- 不迁移到 DeepSeek Harness（developer preview，API 不稳定；复用自研 harness）。

### 2.2 AeroWF 复现进展（另一台服务器，RTX 3090）

- 四机场 Aero-Task 数据已核验：train 75,880 / val 16,260，输入 96 步 × 11 维跑道特征；test 保持锁定未访问；
- 官方代码已修复三处 bug：模型文件语法错误、随机/因果遮挡概率判断错误、遮挡重建 MSE 分母错误；
- **作者已确认（2026-08-23）**：公开仓库为中间版本，论文数字无法完全复现；遮挡率矛盾已澄清（40% 为预训练、25% 为下游）；超参允许按情况改动；作者认为模型仍有很多可改进之处；
- **基线决策**：以修复后代码本地跑出的 3–5 seed × 3 任务结果作为唯一正式基线，论文中记为 **AeroWF†（repaired re-implementation）**，与 KDD Table 3 数字明确不可比、不混表；
- 逻辑回归对照：Balanced Accuracy 0.333 → 0.668，Macro-F1 0.244 → 0.381（数据可学习，雾/霾少数类困难）；
- 小规模 pilot（每机场 500 train / 100 val，1 epoch）：固定 25% 遮挡下 MSE 0.23433 / MAE 0.41537；独立评测程序与模型内部 MSE 误差约 1e-9，评测正确性已验证；
- 完整数据 1 epoch 容量测试：train loss 0.14403，随机 mask val loss 0.08653，**68 秒/epoch，峰值显存 3.29 GB**（batch 128）；
- 正式 30 epoch Scratch 实验已配置，预计 35–45 分钟/次。

**推论：单个 trial ≈ 0.75 GPU 小时，一张 3090 可并发 2–3 个 trial。算力不是瓶颈，日历和决策顺序才是。**

### 2.3 Harness 现状（对照闭环愿景图，分三级）

**A. 已具备且实战验证：**

- 完整闭环骨架：proposal → action 校验 → 真实 GPU 执行 → 冻结外部 evaluator → DecisionPolicy → lineage/memory → 下一轮 proposal；
- 多指标 guardrail 决策与回滚（旧 Radar 上 alpha=1.5 候选因 MAE/SSIM 越界被自动拒绝并回滚，是实证）；
- H1–H5 加固全部验收：campaign 预算持久化、阶段重入、decision/memory 单次 finalization、preflight 强制 digest gate、accepted→promote→freeze 合成路径；
- test lock + Test Custodian + 一次性认证机制；artifact digest / SHA-256 审计链；680 项测试（6 个失败在无关的 code_task/greenfield 路径）。

**B. 已具备但从未实战使用（必须验收，不能默认成立）：**

- 多轮无人值守 discovery：历史仅真跑过两轮单变量 alpha 试验；
- accepted 候选晋升为新 parent 的路径：只过了合成测试。

**C. 不存在，需新建（详见 04 文档，估 5–8 人天）：**

- AeroWF adapter（`[B,R,T,F]` 数据访问、训练入口、预测合同）；
- AeroWF endpoint 网格 evaluator；
- 双轴动作空间 schema 与 config/code-diff 执行器；
- 三类隐藏认证环境实例化；
- 面向本任务的 LLM proposal 提示与证据注入。



### 2.4 旧资产处置

- 旧 Radar campaign：`frozen_legacy`，不再产生任何 GPU 任务；G1 因 MAE 相对标准差 8.5%>5% 被拒的经历，作为"治理会拒绝自己人"的方法论案例写入论文；
- SEVIR：搁置（数据一个字节未下载，起步成本远高于 AeroWF）。

## 三、必须立即冻结的四个决策（8/25 前）



### 3.1 ZBAD 整库留出，做空间认证

parent 只在 ZBAA/ZSPD/ZSSS 三机场上训练与搜索；ZBAD 全部约 27,101 样本封存为**空间迁移认证集**，训练与搜索全程不可见。这复用了 KDD 论文 few-shot 一节"ZBAD 是未见机场"的设定，叙事自洽。**该决策必须先于一切基线重跑**——四机场混训的基线在此设计下作废。

### 3.2 Purge gap 重切分

96 步滑窗跨 70/15/15 时间边界会共享最多 95/96 个时间步。在每个切分边界删除 96+forecast horizon 步内的样本（样本损失 <1%）。**做完此步后，KDD Table 3 的数字不再是我们的 baseline；协议 v1.0 是唯一真值，Table 3 仅作参考。** 这在论文中如实说明（我们修了公开代码 3 个 bug + 加了防泄漏切分，数字有差异是预期内的）。

### 3.3 Endpoint 网格

评测器从第一天起按 (任务 × 时效 × 机场) 网格输出：

- 预测：wind MAE/RMSE × {T+1, T+4, T+8} × 3 机场 = 9 组；
- 分类：危险天气 CSI / Macro-F1 × 3 机场 = 6 组；
- 插补：{25%, 50%, 75%, feature} MSE/MAE × 3 机场 = 12 组（时间不够时首先砍这组）。

约 20–27 个配对 endpoint。这是 val→test 迁移分析具有统计内容的前提，弥补"单数据集"相对分子论文 36 个 endpoint 的先天劣势。

### 3.4 两个轴与预注册接受规则

- **Representation 轴**（只许改特征/输入编码文件）：跑道坐标系顺风/侧风/阵风侧风分解、风向周期编码、露点差、气压趋势、METAR 特征工程；
- **Objective 轴**（只许改损失/目标文件）：horizon 加权损失、危险天气事件加权、时距条件化的对齐权重（tier-2，需预训练）、分类 focal 参数化变体；
- 文件级 axis lock：每个 trial 只允许一个轴的白名单路径出现 diff，越界直接拒绝（harness 已有同类机制）；
- 接受规则在第一个正式 trial 之前冻结：主 endpoint（预测网格）配对均值改善 ≥ 预设门槛，guardrail endpoint（分类 CSI 等）恶化不超过预设容差，**用配对差值 + 按天气事件/日期块的 block-bootstrap CI，不用一刀切相对标准差**（旧 Radar G1 的直接教训）。
