## 〇、红线纪律

1. 收到 B 封存移交的认证数据（三机场 test 尾部 + ZBAD + event 切片）后，**除 9/11–9/12 的一次性认证外不得评测任何模型**；
2. 封存后**退出一切候选讨论**：不评价动作、不建议方向、不透露认证数据的任何统计特征；
3. discovery 期间（9/1–9/9）你回传给闭环的只有**聚合指标**，不回逐样本/逐事件分数（防止通过分数差分定位验证样本）；
4. evaluator 冻结后修改必须升版本 + 保留旧版 + 书面理由；**禁止因候选结果不理想调整指标或门槛**；
5. 认证只执行一次；执行后立即重新上锁，不接受"再测一次"的任何请求（含导师口头请求——要求书面并留痕）。

## 一、任务清单

### C1｜Evaluator v1.0（8/24–8/29，8/29 冻结）★核心交付

**Endpoint 网格定义**（输出必须逐项落盘）：

| 组 | 指标 × 维度 | 数量 |
|---|---|---|
| 预测 | wind MAE、RMSE、Crosswind MAE × {T+1,T+4,T+8} × 3 机场 | 9–27 项 |
| 分类 | 危险天气 CSI、Macro-F1 × 3 机场（+ 雾/霾少数类 F1 单列） | ~9 项 |
| 插补 | MSE、MAE × {25%,50%,75%,feature} × 3 机场（固定 mask） | 24 项 |

**必须冻结的口径**（写入 `evaluator_config_v1.json` 并 digest 化）：

1. 聚合方式：先按机场内 micro 汇总，网格均值为各 endpoint 等权平均；overall 与逐 endpoint 同时输出；
2. 插补固定 mask：预生成 mask 文件（固定 seed）+ 哈希，所有 trial 共用（你们已有 fixedmask 评测程序，收编升级）；
3. 分类零分母：固定报 `null` + `undefined_zero_denominator` 计数，不作 0 处理；
4. 异常语义三态：`invalid`（提交违反接口：NaN/Inf、shape 错、sample_id 缺失/重复/未知）/ `failed`（评测器或基础设施故障）/ `completed`；前两者是 `not_evaluated`，**不得自动视为候选失败**；
5. 预测值越界：禁止静默 clip，报告 out-of-range 计数并标记 invalid；
6. **block-bootstrap CI**：抽样块 = 连续日期块（建议 24h）或天气事件块，二选一后冻结；禁止按滑窗样本独立 bootstrap（重叠窗口不独立）；
7. 接口：模型侧只提交 `predictions.npz`（pred + sample_id），真值由你按 sample_id 本地对齐；`allow_pickle=False`。

**边界测试**（全绿才算冻结）：NaN/Inf 输入、错误 shape、ID 乱序/缺失/重复、越界值、空提交、固定 mask 哈希不匹配——每类至少一个用例。

交付：evaluator 代码 + config + 测试报告 + digest 清单；以 subprocess 方式接入 A 的 harness（8/28 起与 A 联调）。

### C2｜认证环境封存（8/25 签收，8/31 前完成封存体系）

三个认证环境：

| 环境 | 内容 | 来源 |
|---|---|---|
| temporal | 三机场各自时间尾部 test | B 移交 |
| spatial | ZBAD 整库 | B 移交 |
| event | 认证数据内的危险天气事件切片（**由你独立定义**，定义规则与 train 侧一致但样本清单不外泄） | 你 |

封存体系（沿用雷达/SEVIR 的 test-lock 模式）：

- `test_lock_state.json`：LOCKED 状态、禁访路径 token、解锁条件（仅 05_certification 阶段 + 冻结记录齐全）；
- `test_access_log.jsonl`：append-only，初始为空；每次访问一行（时间、目的、候选 digest、执行人）；
- 认证数据物理隔离：独立目录 + 权限，不进 A/D/E 可读路径，不进任何 agent 可见文件系统。

### C3｜接受规则实现与冻结（8/29–8/31）

- 与 A、导师定稿 DecisionPolicy 数值：主 endpoint（预测网格）配对均值改善门槛、guardrail（分类 CSI、少数类 F1）恶化容差；
- 实现为配置文件 + digest；**冻结时间必须早于第一个正式 discovery trial**（9/1）；
- 保留旧版原则：若日后升版，必须书面说明依据且不得回溯适用。

### C4｜Discovery 期间的评测服务（9/1–9/9）

- 每个 trial 输出 `metrics.json`（全网格 + 异常计数 + 状态）+ `evaluation_manifest.json`（预测/数据/config/代码 digest、split、样本数、UTC）；
- 只回聚合指标（见红线 3）；
- 每日向账本报：completed / invalid / failed 计数。

### C5｜一次性认证（9/11–9/12）★全项目最关键 48 小时

执行顺序（每步留痕）：

1. 核验候选冻结记录齐全（commit、config、seed、checkpoint digest，由 A 提交）；
2. `test_access_log` 追加解锁记录 → 解锁；
3. 评测对象：{parent, 随机臂最佳, LLM 臂最佳,（如有）Optuna 臂最佳} × {temporal, spatial, event} × 全网格 × 全部确认 seed；
4. 立即重新上锁 + 追加记录；
5. 出 `certification_report.json`：逐环境逐 endpoint 配对差值 + CI + guardrail 通过情况 + 最终结论；
6. 结论三类如实标注：transferred / validation-only（non-transfer）/ inconclusive。

## 三、失败处置

- C1 延误 >2 天：先砍插补 endpoint 组（24 项），保预测+分类网格；
- 联调发现 harness 侧接口不符：以你的 evaluator 合同为准，A 改 adapter；
- 认证中发现 invalid/failed：如实记录，**不给任何一方重交机会之外的特殊处理**（重交仅限修复接口性错误且留痕，禁止改模型）。
