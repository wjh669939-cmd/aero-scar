## 一、任务清单（按截止日排序）

### B1｜三机场重切分 + purge gap + ZBAD 封存（8/24–8/25）★最高优先级，阻塞所有人

- 切分设计（**本质是"KDD 原切分 + 修剪"，不是重新划分**：时间边界、预处理、样本构造全部沿用原样；只做删跨界窗口和抽出 ZBAD 两件事）：
  - ZBAA / ZSPD / ZSSS 三机场，沿用 KDD 原时间边界的按时间顺序 70/15/15（train/val/test）；若原边界时间戳可从代码/数据中恢复则直接复用并记录，不自行重划；
  - **ZBAD 全部样本（约 27,101）单独成库，不切分**，整体作为空间认证集；
  - **purge gap**：每个 train/val、val/test 边界删除跨界滑窗，gap ≥ lookback(96) + 最大 horizon(8) = **104 个时间步**（按实际采样间隔换算并写入文档）；样本损失预计 <1%，需报告确切数字；
  - 分类/插补任务若共用滑窗索引，同一 gap 规则统一适用。
- 交付物：
  - `split_manifest_v1.json`：每样本 sample_id、机场、时间范围、split、是否被 gap 剔除；
  - `data_contract_v1.md`：字段、shape（`[B,4,T,11]` + runway_mask）、归一化定义与统计来源、缺失值规则；
  - `checksums.sha256`：全部数据文件与 manifest 的哈希；
  - ZBAD 库与三机场 test 尾部的**封存移交记录**（交 C 签收）。
- 验收：A 用 manifest 能独立重建任一样本；gap 边界抽查无跨界滑窗；导师确认 ZBAD 留出决策。

### B2｜Aero-Pre2020 预训练数据确认 + 成本实测（8/25–8/26）

- 确认 139,878 样本预训练库是否在手、完整、可加载；
- 与 D 配合跑预训练 1 epoch，记录 wall-clock 与显存（tier-2 与"Scratch vs 预训练"对照的成本依据）；
- 预训练数据同样出 manifest + 哈希；确认其时间范围（2020）与下游（2025）无重叠——如有重叠立即上报；
- **★检查预训练语料的机场构成：是否包含 ZBAD？** 若包含，上报并触发决策：(a) 三机场重新预训练（多一次预训练成本），或 (b) 空间认证主张措辞降级为"discovery 与微调阶段未见的机场"。此决策影响论文 claim，须导师拍板；
- 交付：可用性结论书面化（能用/不能用/部分能用 + 原因）。

### B4｜Issue-time 因果审计（8/27–8/29）★发现泄漏立即上报，全组停下先修

审计问题清单：

1. 每个样本 96 步窗口内广播的 METAR，其签发时间是否全部 ≤ 预报起报时刻？
2. 是否存在事后修订报文（COR/RTD 类）被当作原始时刻数据使用？
3. AWOS 与 METAR 的对齐是否引入未来信息（如用窗口末端之后的报文填充）？
4. 插补任务的 mask 是否可能泄漏被 mask 值的统计信息？

交付：`issue_time_audit_v1.md`，逐条给出"通过/不通过 + 证据"；不通过项给修复方案与重跑影响评估。
