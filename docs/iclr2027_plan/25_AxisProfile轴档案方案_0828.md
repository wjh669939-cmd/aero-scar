## 一、要解决什么问题

轴定制目前散落在五处：

`action_registry` · `axis_lock` · `context_assembler` · `discovery_runner`（文件映射 / 签名 / 冒烟假张量）· 共享证据表

单人维护尚可；**三 owner × 三机并行时，人人改共享 runner → 合并冲突 + 一处改坏全轴遭殃**。

目标：每轴一个自包含目录；owner 只碰自己的档案；共享内核仅统筹改。

## 二、目录约定

根路径（建议，实施时定）：`clh_deploy/discovery/axis_profiles/`

```
axis_profiles/
  representation/          # R 轴
  objective_tier1/         # O tier-1（损失）
  objective_tier2/         # O tier-2（预训练目标）
  model/                   # M 轴（DEC-001 激活前可为 stub）
  _shared/                 # 只读公共说明（可选）
```

每轴目录固定五件 + 一本账：

| 文件 | 职责 | 治理级 |
|---|---|---|
| `profile.json` | 轴名、可编辑文件列表、trial 序号段、模板引用、激活状态 | **契约级** |
| `interface.md` | 接口合同（组装进提示词） | **契约级** |
| `smoke_test.py` | CPU 冒烟闸门（假张量 / 静态检查） | **工程级** |
| `free_guidance.md` | 自由提案轴特定指引 + `non_expressibility` 示例 | **工程级** |
| `validators.py` | 额外校验（M 轴必有；其它轴可空实现） | **工程级** |
| `CHANGELOG.md` | 本轴工程级改动流水账 | 强制 |

`profile.json` 最小字段草案：

```json
{
  "axis_id": "representation",
  "display_name": "R",
  "status": "active",
  "trial_seq_range": [100, 199],
  "editable_paths": ["..."],
  "template_ids": ["R1", "R2", "..."],
  "free_guidance_inject": true,
  "owner": ""
}
```

序号段预分配（防多机 trial id 碰撞，驱动已支持 `--start-seq`）：

| 机 / 轴 | 段 |
|---|---|
| R | 100–199 |
| O tier-1 | 200–299 |
| O tier-2 | 300–399 |
| M（激活后） | 400–499 |

## 三、各轴定制要点（自由提案侧）

| 轴 | 自由空间 | 主风险 | profile 定制重点 |
|---|---|---|---|
| **R** | 特征构造，面最大 | 泄漏（禁用列 / 未来信息） | `free_guidance` 强调 `FORBIDDEN_INPUT_COLUMNS` + issue-time；smoke 加静态检查「禁用列名未出现在代码」 |
| **O-t1** | 损失函数族 | 数值不稳（NaN / 梯度） | 指引：损失须对 \[0,1\] 归一尺度有意义；给非对称/分位数/事件加权等机制词汇 |
| **O-t2** | 预训练目标（多文件） | 改面大；模板少，**最先触发强制自由** | 保留 axis_lock 人审 diff 兜底；指引锚定「预训练–下游对齐 / 负迁移」 |
| **M** | 结构改动 | 参数爆炸、形状漂移 | **唯一需要实体 `validators.py`**：±5% 参数预算、IO 形状、前后向冒烟；指引嵌 KDD 消融表 |

与 22 文档关系：触发 / 真实性 / 三类别记账 / 零特权评价 **不变**；本方案只把「轴特定提示与闸门」从散落代码收成档案。

## 四、治理分级（写死）

| 级别 | 文件 | 谁改 | 流程 |
|---|---|---|---|
| **契约级** | `profile.json` 可编辑路径、`interface.md` | 等价 axis_lock | 冻结变更流程 + 统筹签字；升版留痕 |
| **工程级** | `smoke_test.py`、`free_guidance.md`、`validators.py` | 轴 owner 自主 | **必须**写 `CHANGELOG.md`；不走契约升版 |

理由：smoke / guidance 只影响**本轴效率与提案质量**，不碰 C evaluator、不碰 decision_policy、不碰认证集——评价权在评测侧与政策，owner 碰不到。

### CHANGELOG 模板（每轴一份）

```markdown
# <axis> CHANGELOG

| 日期 | owner | 文件 | 改动摘要 | 原因 |
|---|---|---|---|---|
| 2026-08-28 | R | smoke_test.py | 加禁用列静态检查 | 自由提案泄漏面 |
```

一条一行即可；站会抽查，不另造审批流。

## 五、三机克隆协议（修订稿）

相对 8/27 对话「六步清单」，按〇③修订：

**克隆前**

1. ~~征得 C 同意再复制私有目录~~ → **取消**；`c_evaluator_private/` 随镜像整盘克隆。  
2. 知会 C 一声即可（保管边界从「单机」变为「三机同权托管」）；禁访 token 与路径约定不变。  
3. CLH `.env` API key 会随镜像复制 → **克隆完成后轮换一次**。

**克隆后（每台约 3h，可并行）**

4. **跨机一致性**：复跑 seed43 full_pipeline，与源机五阶段指标对账（预期 bit 级一致，同 G-8）。过则 parent 参考值直接平移；不过则该机自建 parent。  
5. 常规三件套：contract_tools 单测、evaluator golden、冒烟闸门自检。  
6. 运行协议：trial 序号按 §二分段；每晚 lineage 合并（`lineage_tools.py` 已备）→ 次日分发正典。自由提案触发只看本轴历史（单机自洽）。

**开克隆时机（不变）**：先看完「一次真闭环」质量（batch03 及筛选信号），再决定是否三机铺开——避免把未验证的提案质量放大三倍烧卡。

## 六、实施节奏（建议，会上可改）

| 阶段 | 做什么 | 何时 | 风险 |
|---|---|---|---|
| A. 骨架平移 | 现有五处配置收进 profile 目录，**行为严格等价**，单测保证不变 | batch03 **跑着的时候**（1–2h） | 纯重构，不改方法学 |

原则对齐既有纪律：**等一次真闭环再动方法学**；A 阶段不违反该原则。
